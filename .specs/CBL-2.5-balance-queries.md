# CBL-2.5. GetBalance, ListEntries (курсор) и снимки балансов

| Поле | Значение |
| :-- | :-- |
| Эпик | E2, Ledger |
| Репозиторий | `cbl-ledger` |
| Размер | M |
| Волна и параллельная группа | W1-LEDGER |
| Зависит от | 2.1, CF-1 |
| Версия контрактов | `cbl-protos@cf-1` (`billing/ledger/v1`, `billing/common/v1`) |
| Статус | done, ревью закрыто |

## 1. Контекст и цель

Читающие запросы леджера: баланс счета (для Billing API `/v1/balances`) и выписка проводок с
курсорной пагинацией (для выписки мерчанта и сверки). Дополнительно закрывается открытый
вопрос 2.2: повтор `PostTransaction` обязан возвращать снимок балансов на момент проводки,
а не текущее состояние счетов (`transactions.balances_after`).

## 2. Границы

In scope: `GetBalance`, `ListEntries` (gRPC, usecase, storage), таблица снимков
`transaction_balances` (миграция 00008), запись снимков в `PostTransaction`.
Out of scope: план счетов и провижининг (2.6), consumer `payment.events` (2.7),
события `ledger.events` (2.7), отчетные выгрузки (ClickHouse, 11.x).

## 3. Функциональные требования

FR-1. `GetBalance(account_id)`:
- счет обязан существовать (`account_not_found`), балансовый ряд обязан существовать;
- ответ: `available` и `reserved` в `Money` (int64 минимальные единицы плюс asset и
  decimals счета); нулевой баланс возвращается как 0/0.

FR-2. `ListEntries(account_id, limit, cursor)`:
- счет обязан существовать; выписка сортируется по `entry_id` по возрастанию (хронология
  append-only); порядок `entry_id` для закоммиченных проводок совпадает с порядком коммитов
  по счету: балансы обновляются CAS до вставки проводок, поэтому проигравший конфликт
  откатывает выданные id и повторяет с большими (ADR-2.5), курсор не пропускает записи;
- курсор - непрозрачная строка (в реализации - десятичный `entry_id` последней записи
  предыдущей страницы); возвращается `next_cursor`, если есть более новые записи;
  пустой курсор - с начала; непарсимый или отрицательный курсор - `invalid_cursor`;
- `limit`: 0 -> 50, больше 200 -> 200 (курсорная пагинация без total);
- ответ: `entry_id`, `transaction_id`, `account_id`, `direction`, `amount: Money`,
  `ref_type`, `ref_id`, `created_at` (из `transactions`), asset/decimals из счета.

FR-3. Снимки балансов: при первой проводке `PostTransaction` в таблицу
`transaction_balances` в той же транзакции БД пишутся строки `(transaction_id, account_id,
available, reserved)` для всех затронутых счетов. Повтор по ключу идемпотентности
возвращает `balances_after` из снимка, а не текущее состояние счетов (закрывает открытый
вопрос CBL-2.2). Для транзакций, созданных до миграции 00008 (dev-данные), сохраняется
прежнее поведение (текущие балансы) - переходное fallback-чтение.

FR-4. Маппинг ошибок: `account_not_found` (not_found), `invalid_cursor` (invalid_argument),
`invalid_account_id` (invalid_argument, транспорт), прочее - internal без деталей.
Причины ошибок не включаются в текст статуса (не утекают детали схемы).

## 4. Контракты

`LedgerService.GetBalance` и `LedgerService.ListEntries` из `billing/ledger/v1` (CF-1):
`GetBalanceRequest{account_id}` -> `AccountBalance`; `ListEntriesRequest{account_id, limit,
cursor}` -> `entries[]`, `next_cursor`. Входные лимиты транспорта: `account_id` - UUID,
`cursor` до 64 символов, `limit` в пределах uint32 (клампится в storage).

## 5. Модель данных и миграции

`migrations/00008_transaction_balances.sql`:

```sql
CREATE TABLE transaction_balances (
    transaction_id uuid        NOT NULL REFERENCES transactions (id),
    account_id     uuid        NOT NULL REFERENCES accounts (id),
    available      bigint      NOT NULL,
    reserved       bigint      NOT NULL,
    created_at     timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (transaction_id, account_id)
);
CREATE INDEX entries_account_id_idx ON entries (account_id, id);
```

Таблица append-only по смыслу (пишется один раз вместе с транзакцией); asset и decimals не
дублируются: читаются соединением с `accounts`. `created_at` готовит партиционирование по
времени (ретеншен и обслуживание - 14.2). Индекс `(account_id, id)` обслуживает выписку:
`entries_account_idx (account_id, created_at, id)` порядок по `id` не дает. `AutoMigrate`
запрещен.

## 6. Конечные автоматы

Не применимо: запросы не меняют состояние.

## 7. Edge cases

Пустой баланс счета (явные нули), несуществующий счет, счет без балансового ряда
(fail-closed `account_not_found`), пустой курсор, курсор последней страницы
(`next_cursor` пуст), курсор из выписки другого счета (принимается: фильтр `id > cursor`),
limit 0/1/200/огромный, выписка счета без проводок (пустая страница без курсора), повтор
`PostTransaction` после последующих операций (снимок), транзакция без снимка (legacy
fallback), конкурентные записи во время пагинации (курсор не пропускает закоммиченное),
мусорный/отрицательный/переполненный курсор.

## 8. Нефункциональные требования

Дедлайн 500 мс (CBL-003); выписка читается индексом `entries_account_id_idx (account_id,
id)` (миграция 00008), снимки - по первичному ключу `(transaction_id, account_id)`; чтения
без явной транзакции БД (автокоммит, без удержания соединений и блокировок записи).
Покрытие unit+integration не ниже 80%.

## 10. План работ и коммит

Коммит `CBL-2.5: балансы и выписка со снимками после проводки`; спека входит в коммит.

## 11. Открытые вопросы и решения

- ADR-2.5: курсор - десятичный `entry_id`; полнота пагинации при конкурентных записях
  обеспечена порядком "id = порядок коммитов по счету": балансы обновляются CAS до вставки
  проводок, проигравший конфликт откатывается целиком и повторяет с новыми (большими) id
  (реализовано переносом CAS перед вставкой в `postOnce`). При шардировании счетов (2.9,
  раздел 3.2; задача 14.6) формат курсора пересматривается, до тех пор клиенты не парсят его.
- ADR: чтения выполняются без явной транзакции БД (автокоммит): снапшот между
  `accounts`/`balances`/`entries` не требуется, соединения пула не удерживаются (T-LED-04).
- Принято с ограничением: невалидный UUID на слое storage возвращает `ErrUnknownAccount`
  (снаружи недостижимо: транспорт валидирует до вызова); отдельная ошибка появится при
  появлении внутренних вызовов чтения (2.7).
- Принято с ограничением: `transaction_balances` растет примерно как `entries`; стратегия
  ретеншена и партиционирования - задача 14.2 (KI-ledger-07); `created_at` уже пишется.
- Открытый вопрос: выписка с фильтрами по активу/типу операции - по мере требований
  Billing API (7.x); текущий контракт CF-1 фильтров не содержит.
- Открытый вопрос (из 2.2): закрыт снимком `balances_after` для повтора.

## 12. Ревью (CBL-001, шаг 6)

Четыре независимых прохода (14.10.2026). Блокеров нет; major (индекс выписки, порядок id и
коммитов при конкурентных записях, жизненный цикл снимков) закрыты, minor закрыты или
зафиксированы.
